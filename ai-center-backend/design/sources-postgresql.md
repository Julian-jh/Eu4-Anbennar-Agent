# Data → Sources · PostgreSQL 后端设计

**实施契约 · 2026-11-26** 工程和部署约定见 [后端开发要求](./backend-requirements.md)。本文是 PostgreSQL 来源的首期契约，供前端、API、worker 和验收共用。

## 1. 管理员的实际流程

以 **Reign register** 为例。管理员填写目标数据库、只读用户名和一次性密码，点击测试。API 真实连接该数据库，确认数据库身份以及请求的 schema 是否可见，返回耗时和脱敏诊断。测试草稿只验证这一次输入，取消后没有新数据源。

管理员随后保存来源，可以显式选择加密保存凭据，供今后同步使用。保存完成即可看到来源详情，此时目录可以为空。点击 **Sync now** 后，前端取得运行 ID，轮询运行状态。发布成功后，**Asset preview** 可按 schema 浏览表、视图和字段。有预览权限的用户可读取指定表的少量当前记录。要把 `public.reigns` 导入仓库，再从 **Datasets → Import tables** 选择已发布的资产。

已保存的连接测试在详情中单独触发。注册来源、执行测试和发布目录分别有自己的结果。首期同步为手动触发，运行记录可供 Jobs 展示。来源停用保留元数据、血缘标识和审计。永久删除、定时同步、重新绑定已有数据集以及其他连接器另行设计。

## 2. 数据模型与不变量

平台内部使用稳定 UUID、UTC 时间和工作区外键。下表为逻辑表及关键约束，具体表名可在建模时映射。业务外键同时验证工作区归属。

| 记录 | 主要字段 | 身份、约束及用途 |
|---|---|---|
| 来源 `sources` | `id, workspace_id, name, corpus, kind, engine, enabled, version, current_config_revision, published_snapshot_id, catalog_access_blocked`，创建与更新时间 | 首期 `kind=database`、`engine=postgresql`。工作区内去首尾空格、忽略大小写的显示名唯一。改名保留 ID。同一个数据库可以按不同账号或范围建立不同来源。 |
| 连接修订 `source_config_revisions` | `source_id, revision, target_generation, host, port, database, username, schemas, tls_profile, credential_version_id, created_by, created_at` | 每个来源的 revision 唯一，记录不可变。连接参数、账号、凭据或发现范围变化时创建新修订。改名及修改语料标签只递增来源 version。 |
| 凭据版本 `source_credential_versions` | 来源、凭据版本 ID、密文、nonce、加密密钥版本、创建时间 | 一个版本归属一个来源。修订引用准确凭据版本，公开结果仅披露是否已配置。清除或轮换后，旧版本不得用于新作业。失效密文按保留策略销毁，审计只留版本标识。 |
| 连接测试 `source_connection_tests` | 测试 ID、主体、可空的来源和配置修订、状态、耗时、诊断码、开始和结束时间 | 草稿测试无来源 ID，也不保存连接正文。已保存来源的测试绑定修订。健康页按当前修订显示测试结果。 |
| 目录同步 `source_sync_runs` | 运行 ID、来源与修订、请求人、状态、尝试次数、租约期限、执行令牌、截止时间、错误码、时间戳、结果快照 ID | 对 `queued/running` 建立“来源 + 修订”的部分唯一约束。同一运行有多次尝试时，以令牌区分写入权限。 |
| 目录快照与成员 | `source_snapshots` 记录来源、修订、运行 ID、发布时间。`snapshot_assets` 记录快照、资产 ID、schema、对象名、种类。`snapshot_columns` 记录成员、列序号、列名、PostgreSQL 类型、可空性 | 一个成功运行最多有一个已发布快照。成员在快照内按资产唯一，列序号在成员内唯一。快照只包含目录元数据。暂存结果按运行 ID 和执行令牌隔离。 |
| 资产身份 `source_assets` | 稳定资产 ID、来源、目标代次、首次发现与最后可见快照、远端关系 OID、对象种类及限定名称 | Datasets 引用资产 ID。已发布目录中消失的对象标为不可用。保留旧资产 ID 及被引用的必要历史。资产行不保存预览数据。 |
| 数据集引用 `dataset_asset_refs` | 工作区、数据集 ID、资产 ID、是否归档 | Sources 读取引用计数并保护身份。以后由 Datasets 在创建、归档、恢复或删除数据集时同事务维护。首期用数据库集成测试夹具提供活跃及归档引用，验证保护规则，无需提前实现导入 API。 |
| 幂等记录与审计 | `idempotency_requests` 存唯一范围、HMAC 指纹、操作 ID、可重放结果及到期时间。`audit_events` 存主体、动作、对象与结果 | 遵循通用要求。幂等记录用于重放，审计用于追溯，两者的保留期可分别设置。 |

**版本的区别。** `version` 用于管理员并发编辑。配置修订固定一次连接所用的参数和凭据。快照 ID 标识一次完整发布。例如，改名仅更新 version。轮换密码更新 version 和配置修订。在原配置上再次同步成功生成新快照，配置 ETag 保持有效。

**资产的身份边界。** 主机、端口或数据库变化表示目标变化。已有活跃或归档数据集引用时拒绝原地换目标，返回 `409 source_in_use` 及引用计数，管理员可另建来源。没有引用时允许换目标，并递增 `target_generation`。同名表在新目标上获得新资产 ID。对同一代次，连续发现时用 schema、对象名、种类和关系 OID 匹配已有资产。改名、重建造成匹配改变，或对象在完整快照中消失后再次出现，按新资产处理。旧对象保留血缘。OID 只用作同一目标的识别线索。Datasets 后续接入时，建立引用与检查或更改目标需锁定同一来源行。

**发现范围。** 初始支持指定 schema 的普通表、分区表及普通视图，列按远端序号返回。schema 初始默认 `public`，显式传入空清单返回校验错误。仅发布源端只读账号有权发现的对象。配置的 schema 不存在或不可访问时记录失败。可见 schema 确实没有对象时，空快照是一次有效发布。目录和“最近一次运行”状态分开保存。

## 3. REST 接口

所有路径以 `/api/v1` 开头。下表中“键”均指 `Idempotency-Key`，写入和重放都重新检查当前权限。列表返回 `items, next_cursor`。游标绑定工作区、筛选与稳定排序。资产目录翻页还绑定快照。首期每页默认 25 项，最多 100 项。

| 方法及路径 | 请求与成功响应 | 权限 / 重试 |
|---|---|---|
| `POST /source-connection-tests` | 提交草稿连接配置和一次性密码。正常完成返回 `200`、测试 ID、`succeeded/failed`、耗时及诊断码。 | 测试连接。键必填。不会创建来源、发布目录或返回业务行。 |
| `POST /sources` | 创建配置，`201` 返回公开来源、ETag 和 `Location: /api/v1/sources/{id}`。 | 管理来源。键必填。保存秘密另需凭据管理权限。 |
| `GET /sources`、`GET /sources/{id}` | 分页列表支持名称、corpus、engine 和启用状态筛选。详情仅返回可公开的配置及 ETag。 | 查看来源元数据。 |
| `PATCH /sources/{id}` | 修改指定字段或启停来源，`200` 返回当前公开配置和新 ETag。配置、凭据、审计及幂等结果同事务写入。 | 管理来源。键与 `If-Match` 必填。替换或清除密码另需凭据管理权限。 |
| `POST /sources/{id}/connection-tests`、`GET /source-connection-tests/{test_id}` | POST 使用当前已保存的配置与凭据真实测试。GET 读取测试状态和脱敏诊断。 | POST 需测试权限和键，GET 需测试权限。草稿结果另限原调用者。元数据读者可从 health 查看成功或失败的摘要。 |
| `POST /sources/{id}/sync-runs` | `202` 返回运行 ID、绑定修订和 `Location: /api/v1/source-sync-runs/{run_id}`。 | 执行同步。键必填。当前修订已有活动运行时返回该运行。 |
| `GET /source-sync-runs/{run_id}`、`GET /sources/{id}/sync-runs` | 单次状态或分页历史，返回尝试次数、起止时间和诊断。成功包含已发布的快照 ID 和资产数。 | 查看来源运行状态。Jobs 和 Sources 共用同一运行 ID。 |
| `GET /sources/{id}/health` | 分别返回当前配置修订、当前修订的最近测试、最近同步运行、最后一次成功发布的时间及修订、目录状态。 | 查看来源元数据。运行状态变化不会导致配置 ETag 变化。 |
| `GET /sources/{id}/assets`、`GET /sources/{id}/assets/{asset_id}` | 列表可按 schema、对象种类和名称筛选，返回快照 ID、稳定资产 ID 和限定名。打开详情时可传 `snapshot_id`，省略时使用当前快照。 | 查看来源元数据。游标绑定首屏快照，建议有效 15 分钟。发布了新快照后，带旧游标或旧快照 ID 的请求返回 `409 catalog_changed`，前端从首屏重取。游标到期返回 `410 cursor_expired`。 |
| `GET /sources/{id}/assets/{asset_id}/preview?mode=masked&limit=15` | 返回 `asset_id, snapshot_id, read_at, columns, rows, truncated`。按当前授权实时读取一批样例，默认 15 行、最多 50 行。 | masked 需 L3，raw 需 L4。响应 `Cache-Control: no-store`。 |

**分级契约。** L1 对应资产列表，L2 对应资产字段详情。L1 调用字段详情或 L2 调用行预览均返回 403。L3 默认预览全列遮罩。L4 需显式传 `mode=raw`，且只有审批通过并能安全表示的字段可返回原值。视图最高 L2。授权策略使用来源 PATCH 的 `preview_columns` 字段，形如 `{"preview_columns":{"<asset UUID>":["country"]}}`；传空映射即收回整份放行清单。配置按当前资产身份及列签名生效。更新需 `manage`、`preview_policy`、当前 ETag 与幂等键。此操作影响后续读取，不改变远端表结构。

如果当前资产没有任何获准且可安全表示的列，请求原值返回 `403 preview_columns_denied`。源端对父表启用了行级安全策略时，直接预览子分区返回 `409 preview_not_supported`，可通过受该策略约束的父表预览。正常发布目录不改变配置版本；如果发布时因资产或字段签名变化而收回了原值列授权，版本和 ETag 随策略更新。

**配置与凭据。** 创建请求包含 `name, corpus, kind, engine, connection`。连接字段为 `host, port`（默认 5432）、`database, username, schemas, tls_profile`。corpus 对应 EU4、Anbennar 或 Real History。服务端使用驱动参数建立连接，托管 TLS 配置与允许访问的目标。远程真实数据库默认校验证书链和主机名。本机开发用的信任策略由平台配置。[PostgreSQL TLS](https://www.postgresql.org/docs/current/libpq-ssl.html)

保存密码必须显式提交 `credential.action=replace` 及只写字段 `credential.password`。创建时省略表示没有保存密码。编辑时若认证目标相同，省略表示沿用，`clear` 表示清除。空字符串不能触发替换或清除。读取响应以 `credential_configured` 表达状态。草稿测试的密码随请求结束丢弃，若决定保存，须在保存请求中明确提交。首期采用只读用户名和密码。无已保存凭据的来源可登记和编辑，已保存来源的测试、同步与预览返回 `409 credential_required`，不会隐式使用主机账号。

**防止凭据跟随地址或账号转移。** 凭据与目标代次、用户名及 TLS 信任配置绑定。更换其中任何一项，若来源已有凭据，操作者须同时有凭据管理权限。在同一事务中解绑原凭据，并按本次请求为新目标显式保存新密码，或将状态设为未配置。修改显示名或 schema 发现范围可以沿用原凭据。连接池按来源与配置修订隔离，修订失效后关闭旧池，正在返回的旧结果不得对外发布。

**一次创建的契约示例。** `POST /api/v1/sources` 携带键后可以只登记公开配置。下例是 HTTP 消息正文示意。

```json
{
  "name": "Reign register",
  "corpus": "Real History",
  "kind": "database",
  "engine": "postgresql",
  "connection": {
    "host": "archive.example.test",
    "port": 5432,
    "database": "atlas",
    "username": "atlas_reader",
    "schemas": ["public"],
    "tls_profile": "workspace-default"
  }
}
```

成功返回 `201`、来源 ID、`version=1`、`current_config_revision=1`、`credential_configured=false`、详情地址和配置 ETag。GET 详情使用相同的公开配置结构。后续用 `PATCH`、新的幂等键和当前 ETag 补录凭据，再分别执行测试和同步。PATCH 只修改传入字段，嵌套 connection 也按字段合并，若提交 schemas 则整体替换。清除密码必须使用专门的 clear 操作。

**测试和预览的实际含义。** 测试在总超时 10 秒内验证网络、TLS、登录和配置的 schema 可见性，给出实际检查项。草稿表单可以展示检查摘要。发布完整目录要执行同步。测试通过不代表用户拥有每张表的读权。首期行预览开放给当前目录中的普通表和分区表，视图先提供字段预览。API 以服务端解析的资产身份构造限定名称并正确引用标识符，源端开启只读事务并应用权限及行级策略。取样时在同一源端只读事务内先对目标关系取得 `ACCESS SHARE` 锁，再核对关系 OID、当前列和权限，按经许可的显式列清单读取。回复前复核来源仍启用且修订和已发布资产身份仍有效，避免已删除重建的同名对象或新增敏感字段意外出现在旧预览中。默认查询超时 3 秒，响应上限建议 256 KiB，达到行数或字节限额时标明截断。预览是有界样本，结果顺序和跨请求数据一致性不作分页承诺。

**错误约定。** 无有效输入、错误端口和暂未支持的来源引擎为 `422`。缺少必需幂等键为 `400 idempotency_key_required`。ETag 冲突为 `412`。来源停用、未同步、目录过期或资产已更换等状态冲突用 `409` 和独立错误码。未知或不属于该来源的资产 ID 为 `404`。实测的认证失败、超时、权限不足是测试或运行的业务结果，保留 `auth_failed / timeout / permission_denied` 等诊断。实时预览访问外部数据库失败时返回脱敏的上游错误，超时用 `504`。校验失败、网络诊断和请求追踪均不回显密码、DSN 或原始业务行。

## 4. 幂等与事务的执行顺序

### 4.1 创建、编辑和测试

1. **创建或编辑。** 完成认证、授权和请求规范化，尝试取得幂等记录。相同范围与键、相同指纹返回已保存的状态码、公开响应与必要响应头。不同指纹返回 `409 idempotency_conflict`。首次编辑才核验 `If-Match`。一次事务完成来源、修订、凭据变更、成功审计与幂等结果。提交失败全部回滚。提交成功但响应丢失，原键重试仍得到原 ID 和版本。
2. **输入发生变化。** 更换连接参数、发现范围、TLS 或凭据时，递增配置修订，并将旧修订的活动同步标记为失效。仅修改名称保留正在运行的同步。停用来源时也撤销其活动运行的发布资格，即使随后重新启用，旧运行仍不得发布。
3. **连接测试。** 先用短事务占用幂等键并登记 `running` 的测试 ID，再到事务外访问远端。收尾事务保存脱敏结果及审计。并发重放遇到进行中的相同测试，返回 `202` 和同一个查询地址。测试完成后重放终态。若执行进程崩溃，超过截止时间后将该测试终结为 `interrupted`。同键可查询该结果，再测用新键。一次性密码只存在于最初请求内。迟到的执行者只能终结仍为 `running` 的本次尝试。健康页不把旧修订通过的测试当作当前修订通过。

### 4.2 手动同步、故障恢复与发布

| 阶段 | 事务与对外行为 |
|---|---|
| 受理 | 在平台短事务内锁定来源，检查启用状态、当前修订与凭据。创建或复用该修订的活动运行，并保存调用者的幂等记录及审计。同键重试重放原 `202` 和同一运行 ID。不同键并发触发同一活动同步，也指向同一运行。运行完成后有意再次同步使用新键。 |
| 领取 | worker 用行锁认领可运行或可回收的任务，提交租约、到期时间和新的执行令牌，再开始网络 I/O。并行 worker 可使用 `SKIP LOCKED` 领取其他任务。[PostgreSQL 行锁](https://www.postgresql.org/docs/current/sql-select.html#SQL-FOR-UPDATE-SHARE) |
| 读取与暂存 | 读取绑定修订的凭据，在目标库使用有超时的只读、一致性快照事务发现对象与列。大目录分批写入平台暂存区，以运行 ID 和执行令牌区分。在同一修订重新扫描时，已有可读的已发布快照可继续使用。首次同步或修订已改变时显示“待同步”。[PostgreSQL 隔离级别](https://www.postgresql.org/docs/current/transaction-iso.html) |
| 发布 | 一个短事务按固定顺序锁定来源再锁定运行，核验来源启用、修订匹配、运行仍为 `running`、租约有效且令牌相同。原子确认该尝试的完整目录、更新资产身份和可用性、切换来源快照指针、标记运行成功并写审计。以运行 ID 唯一约束防止重复发布。 |
| 失败及重启 | 临时网络故障按有上限的退避重试，建议最多 3 次。无效凭据和权限不足直接终结并给出诊断。租约过期可由其他 worker 重新认领。旧执行者无法续租、发布或覆盖新状态。过期暂存结果按运行和令牌清理。提交发布后 worker 崩溃，恢复时识别已成功状态。 |

运行状态为 `queued → running → succeeded / failed`。可重试的尝试可以回到 `queued`。重新领取时仍使用原运行 ID。来源配置变更或停用，可将其 `queued` 或 `running` 作业置为终态 `superseded`。

| 当前情况 | 前端展示与读取规则 |
|---|---|
| 从未成功发布 | 显示“尚未同步”。此时无可读资产目录。 |
| 同一修订重新同步时发生网络故障 | 显示本次失败、上次成功时间及可继续使用的完整快照。 |
| 当前修订的已保存连接测试或同步确认认证失败或 schema 权限被撤回 | 记录失败并关闭目录和预览读取。该修订再次成功发布后才重新开放。外部权限与缓存元数据之间存在探测时间差，实时预览始终检查源端权限。 |
| 配置修订变化，或来源停用 | 保留最近发布的时间与归属修订，分别显示“待同步”或“已停用”。资产 API 与旧游标统一检查来源启用、发布修订、访问状态和快照 ID。 |

## 5. 前端与验收

**现有页面对接。** Sources 通过同源 API 读取来源和资产，详情与深链采用服务端 ID。连接测试、发布目录和读取样例分别触发。资产列表按游标分页，选中资产后读取字段，点击加载样例后才提交该级别的行预览请求。工作台移除原有演示连接，保留其他菜单中已有数据集的物化记录与来源名称。访问令牌只在当前页面内存中保存。[Sources 前端设计](../../ai-center-frontend/data-menu/README.md)

| 验收场景 | 可观察结果 |
|---|---|
| 输入正确和错误密码分别测试，随后取消草稿 | 可区分通过、认证失败或超时。来源与数据集数量不变。数据库、日志和错误响应中无一次性密码或样例行。 |
| 两个客户端并发创建，或提交成功后断开响应再重试 | 同键同内容只产生一个来源。不同载荷复用键返回 409。不同主体不能通过相同键读取他人的结果。 |
| 同键重试一次换密。两人使用同一 ETag 编辑 | 换密只生成一个新凭据版本。独立的过期编辑返回 412。原成功请求重放返回原版本。 |
| 先发布含两张表的目录，让下一次同步在读取字段时发生网络中断 | 列表仍是一份完整旧目录，最新失败单独可见。来源同步从未创建数据集。 |
| 双击同步、worker 读取中被终止，或在提交发布后被终止 | 只有一个活动运行与最多一份成功快照。接手者能恢复，迟到尝试不能发布。 |
| 同步 A 期间换成 B 或停用后再启用。A 与 B 都有 public.reigns | 旧运行不能覆盖新来源目录。无引用时 B 的同名表取得新资产 ID，B 从未收到 A 的旧密码。已有活跃或归档引用时换目标被拒绝。 |
| 源表消失或被同名重建，或轮换到权限更少的账号 | 旧资产引用仍可追踪，不能借旧 ID 或旧游标读取新对象或已撤权内容。新修订发布后只展示新范围。 |
| 仅有元数据权限，随后授予预览权限 | 前者可读已发布字段，读取样例行被拒。后者按只读账号权限及限额取样。API 和 worker 重启后来源 ID、运行和快照保持可查询。 |

**本地验收。** 用各级凭据对同一个已同步资产先请求目录，再取字段、默认样例和获准列原值。更换来源账号后，用旧资产 ID 再试，验证访问立即关闭。启动、迁移和测试命令见 [Sources 后端运行说明](../README.md)。
