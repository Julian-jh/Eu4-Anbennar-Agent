# 后端开发要求

**开发基线 · 2026-11-26** 已确认 Python、FastAPI、REST 和 PostgreSQL 首发。首个模块的字段、端点和验收场景见 [Data → Sources · PostgreSQL](./sources-postgresql.md)。

## 1. 运行方式与模块边界

| 部分 | 基线 |
|---|---|
| API | Python + FastAPI，以 Pydantic 定义带类型的输入和独立的公开响应模型。提供版本化 REST 接口和 OpenAPI 契约，供管理前端与 CLI 共用。 |
| 元数据库 | 使用独立的 PostgreSQL 数据库保存平台状态。SQLAlchemy 管理平台数据访问和事务，Alembic 管理表结构版本。源端 PostgreSQL 使用单独的连接配置、连接预算和只读账号。 |
| API 与 worker | 同一代码库、两个可独立重启的进程。API 处理认证、授权、短请求和任务受理。worker 从 PostgreSQL 任务表领取长任务。首版只需一套持久化任务设施。 |
| 部署 | Windows 本机、单工作区。API 默认只绑定回环地址，浏览器通过同源入口调用。平台数据库可在本机或同机容器运行。后续读取受管目录时，以 worker 所在机器及其 OS 服务账号的可读范围为准。 |
| 模块 | REST 层负责验证和序列化。应用服务决定权限、幂等与事务边界。持久化层负责约束和锁。连接器负责访问外部数据。路由和 worker 调用同一应用服务。定时器将来可以复用任务受理协议。 |

FastAPI 的类型化 OpenAPI 契约、SQLAlchemy 的事务管理与 Alembic 的版本化迁移各有独立职责。[FastAPI](https://fastapi.tiangolo.com/features/) · [SQLAlchemy 事务](https://docs.sqlalchemy.org/en/20/orm/session_transaction.html) · [Alembic](https://alembic.sqlalchemy.org/en/latest/tutorial.html)

## 2. REST 与身份

- 统一前缀为 `/api/v1`。服务端生成稳定 ID，时间用带时区的 UTC 时间戳。集合响应提供受限分页和稳定排序。错误统一返回 `code`、面向操作者的 `message` 和 `request_id`。重试建议通过 `retryable` 或 `Retry-After` 表达。
- 短请求在事务提交后返回成功。长任务持久化后返回 `202 Accepted`、任务 ID 和可查询的 `Location`。操作已受理、远端连接通过、目录已发布是三个独立状态。
- 单工作区同样要求真实身份。建议首版本地管理员通过初始化流程获取登录凭据。浏览器使用服务端会话及 HttpOnly、SameSite Cookie，写操作验证来源和 CSRF 令牌。CLI 凭据按权限和期限签发。工作区和主体从认证上下文取得，服务端对每个资源重新授权。
- 连接测试、查看目录、读取样例行、管理连接与修改凭据使用独立能力。启动时可以把能力都授予本地管理员。接口必须能在验收时分别授予和拒绝。未认证返回 `401`，缺少操作权限返回 `403`，其他工作区的资源按未找到处理。
- 传递真实凭据的服务入口使用 HTTPS。回环 HTTP 可供使用专用测试凭据的本机开发环境使用。浏览器的本地样例、`localStorage` 和界面角色文字都不作为服务端身份或配置来源。

## 3. 幂等、并发与事务

1. **一次用户意图对应一个幂等键。** 客户端在首次提交前生成 `Idempotency-Key`，超时重试复用原键，用户有意再次执行则生成新键。每个需去重的端点在模块契约中标出。服务端以工作区、调用主体、操作、目标和键为唯一范围，用数据库唯一约束处理并发请求。
2. **记录可以安全重放的结果。** 幂等记录保存规范化请求指纹、状态、公开响应或结果引用、创建与到期时间。建议已结束的请求至少保留 24 小时，在关联任务结束前保留其记录。窗口内同键同请求重放，同键不同内容返回 `409`。窗口外不承诺按旧键重放。指纹使用服务器密钥 HMAC，覆盖有意义的输入、凭据操作及写入前置条件，密钥与数据加密密钥分离。请求正文、明文密码和样例行均不落入幂等表。
3. **防止覆盖同事的修改。** 读取可编辑配置返回强 ETag，修改携带 `If-Match`。首次请求缺前置条件返回 `428`，过期返回 `412`。已授权的同键重放优先于重新校验旧 ETag，避免已成功但丢失响应的重试误报冲突。[HTTP 条件请求](https://www.rfc-editor.org/rfc/rfc9110.html#name-if-match)
4. **ACID 覆盖平台数据库内的业务结果。** 资源与版本更新、成功审计、幂等结果在一个短事务内提交。任务受理与业务结果发布分别有自己的提交点。外部连接或扫描期间释放平台事务。只有完整、经版本校验的结果可以对读者可见。数据库约束和行锁承担并发裁决，应用层预检查负责给出友好提示。[PostgreSQL 事务](https://www.postgresql.org/docs/current/tutorial-transactions.html)
5. **任务可恢复。** worker 短事务认领任务，写入租约、过期时间和递增执行令牌。执行在事务外进行。续租、发布和终结必须匹配令牌。租约过期后其他 worker 可重新认领。允许外部只读操作重复，平台业务结果最多发布一次。失败记录使用独立事务保存，业务回滚后仍可排查。

指纹记录同时保存算法和 HMAC 密钥版本。平台轮换密钥时，为尚在重放窗口内的记录保留旧验证密钥，保证原请求仍能与原指纹匹配。重放前仍检查操作者目前的权限。

## 4. 敏感数据与运维

- **凭据生命周期**　区分一次性测试与显式保存。保存时通过成熟加密库实施认证加密，密文、随机 nonce、密钥版本和凭据修订可在平台库内事务提交。主密钥放在数据库外，本地建议由 Windows 服务账号保护，API 与 worker 仅获得所需访问权限。备份应包含可恢复的密文与独立保管的密钥恢复材料，并验证恢复流程。
- **外部访问**　由服务端维护允许的主机、网段、端口和信任的证书。允许管理员明确登记所需内网目标。建立连接时检查实际解析地址及出站策略。连接、查询、并发、返回行数和字节数均有限额。未来的文件连接器还需校验解析后的真实路径及目录边界。
- **审计与观测**　记录主体、工作区、动作、资源 ID、修订、成功或失败、公开错误码、时间及请求或任务 ID。配置变更只记录允许的变更字段。日志、异常、链路追踪和验证错误均过滤连接串中的秘密、凭据输入和预览内容。运营指标至少覆盖请求失败率、排队时长、执行耗时、租约重试次数与最后一次成功发布的时间。
- **升级与测试**　依赖锁定到经验证的版本。每次结构变更提供可审查的 Alembic 迁移，发布前验证从上一版有数据的数据库升级，记录备份恢复或兼容回退方式。用真实 PostgreSQL 分别测试平台库和只读来源，覆盖约束、并发、事务回滚、最小权限、进程中断、脱敏以及前端和 CLI 对同一契约的调用。

## 5. 数据预览分级

授权必须由服务端在每次访问时判断。工作区决定可以访问哪些来源。平台预览级别、对象种类、列授权与源端只读账号的权限共同决定实际可见范围。查看级别逐级包含上一级；管理来源、保存凭据、测试连接、执行同步、授权原值列是彼此独立的操作权限。

| 级别 | 可见范围 | PostgreSQL 来源示例 |
|---|---|---|
| L1 目录 | 对象名、种类、所在 schema | 看见 `public.reigns` 出现在目录中。 |
| L2 字段 | 目录及字段名、类型等结构信息 | 看见 `country` 与 `internal_note` 两列。视图到此为止。 |
| L3 脱敏样例 | 有限行的存在性、列布局与固定遮罩 | 即使获准显示的列也先遮罩。首次请求样例默认使用此级。 |
| L4 获准列原值 | 明确请求原值时，仅可取得管理员为当前资产和列签名放行的值 | 只放行 `country` 后可见国名，`internal_note` 继续遮罩。新列默认遮罩。 |

原值放行由拥有策略管理权的操作者维护。表被同名重建、列签名变化或连接修订变化，必须重新核验原值授权。预览行按需在目标库读取，数据库可见性和行级策略持续生效。业务值不进入平台目录、审计、幂等记录或缓存。

### 已确认的凭据和同步边界

- 草稿测试只使用本次请求输入的密码。后台同步凭据需显式保存，密码仅以认证加密密文落库。更换数据库目标、账号或信任配置时解除旧凭据绑定。
- 同一修订遇到网络故障，继续提供最后一次完整发布的目录，并单独展示失败。切换连接修订、停用来源或确认认证、schema 权限失效，即刻阻断旧目录与行预览。当前修订成功同步后重新开放。

### 首期本地实现

单机 API 与 CLI 使用有期限的 Bearer 凭据，权限清单保存 token 摘要。预览返回前再核对一次主体、权限、来源修订、快照和列策略。API 与 worker 分别启动。更换或清除来源密码时，平台库在同一事务内清除旧版本的密文和 nonce，保留版本标识供审计；既有备份和 WAL 按各自保留期处理。幂等记录至少保留 24 小时；异步操作从终态起计算，worker 分批清理。运行方式见 [Sources 后端说明](../README.md)。

## 6. 首期交付边界

第一里程碑完成 PostgreSQL Sources 的真实连接、手动目录同步和限量预览。数据库表的选择、批量入仓继续归 Datasets。EU4 受管目录、Anbennar Git 和 Wiki 是后续连接器。它们可以复用权限、任务和审计，不占用首期接口的实现范围。现有浏览器样例保留在演示模式，进入真实工作区由管理员显式配置来源和凭据。
