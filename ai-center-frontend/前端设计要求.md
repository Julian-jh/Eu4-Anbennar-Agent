# AI 配置平台前端设计要求

通用原则适用于 Data、Semantic layer、AI Center、External APIs 和 Workspace settings。按任务查找具体要求时，可从[目录版](./前端设计要求目录版.md)进入对应小节。

## 通用原则

<a id="principles-navigation"></a>

### 1. 导航表达层级，同级页面通过共同入口切换

顶栏切换功能区，功能区导航切换子菜单，详情标签切换同一对象的视图。列表可以打开详情，左箭头返回来源列表并恢复目录和筛选。同级切换统一走共同导航。正文引用其他对象时展示名称和状态，刷新、归档等操作在原处反馈结果。

<a id="principles-actions"></a>

### 2. 按操作对象决定入口和按钮位置

跨多个资产的管理任务使用独立子菜单。作用于单个对象的操作放在详情，例如在表详情刷新当前表，在 Jobs 集中调查多张表的失败作业。目录操作靠目录，整表操作靠详情标题，字段和单元格操作靠对应值。同一任务可以有单项和批量入口，两处共享同一份配置。

<a id="principles-layout"></a>

### 3. 把空间留给当前任务，用对齐和间距表达结构

导航已经标明页面名称时，正文直接从筛选、工具或内容开始。具体的表名、作业编号等识别对象的信息仍需可见。目录树紧靠子菜单，筛选区贴齐上方和左侧边界，结果列表独立铺开。用留白、底色和细分隔线区分区域，减少重复标题和多层卡片。

<a id="principles-scale"></a>

### 4. 根据数据规模和选择任务安排控件

有层级的资产用目录树浏览，搜索与筛选作用于当前范围。移动位置时，在树形弹窗中展示完整目标路径，确认后生效。长列表按需分页，多选应跨搜索、跨页保留。需要选择来源、勾选多项、指定目标并核对结果的流程使用独立页面。

<a id="principles-fields"></a>

### 5. 独立属性分别配置，表单随对象类型变化

可以独立变化的属性要分别选择、保存和清除。业务允许时可以留空、分步补全，例如给一张尚无业务域的表添加主题。数据库、目录、文档和结构化表各自展示相关字段。多种方式都能创建同类对象时，入口名称要说明各自使用的输入和产生的结果。

<a id="principles-workflow"></a>

### 6. 把配置、执行和观察放在各自合适的位置

配置页定义规则，预览或测试页使用规则，运行详情解释结果。例如，检索页配置字段和索引，预览页放查询条件、行数上限、执行按钮与结果。血缘等关系图从具体对象进入。界面应说明配置何时生效、是否需要重建，以及测试实际验证了什么。

<a id="principles-feedback"></a>

### 7. 操作有稳定的顺序、尺寸和反馈

选中对象后显示已选数量和批量工具栏。同组操作按钮等宽等高，相关输入和执行按钮对齐。清除选择在前，永久删除在最后。确认归档或删除前说明影响哪些对象、能否恢复以及相关依赖。批量执行后能查到成功项、失败项和具体原因。

<a id="principles-accessibility"></a>

### 8. 全平台保持一致的视觉和交互语言

暗色主题以黑、白、灰为主，少量有明确含义的操作使用强调色。状态同时用文字表达。顶栏图标位置稳定，悬停或键盘聚焦时名称从下方滑入，长名称在原位显示。图标按钮提供可访问名称，触屏支持直接操作，窄屏保留相同的阅读顺序。

<a id="implementation"></a>

### 前端代码组织

按功能菜单组织目录。同一种交互由单项和批量入口复用，例如移动一张表和移动多张表共用文件夹选择器。Data 的前端实现集中在 [data-menu](./data-menu/)。

## 工作台

<a id="shell-navigation"></a>

### 顶栏、同级导航与返回

- 五个主功能区图标在顶栏等距排列。鼠标悬停或键盘聚焦时，图标向上移出，名称从下方滑入同一个按钮。离开后反向切回。长名称可在按钮内换行，相邻图标保持原位。触屏轻点一次即可导航并短暂显示名称，启用减少动态效果时直接切换。按钮保留可访问名称和当前功能区标记。
- 菜单页保留可访问的页面名称。详情中，从 **Overview** 切换到 **Schedule** 使用当前表的标签栏。查看另一张表或另一条作业时，先返回来源列表。详情正文中的上游表名和重试记录作为只读信息展示。
- 目录、文件夹和表详情有可分享的地址。浏览器前进、后退和刷新应恢复相应视图。

<a id="shell-theme"></a>

### 主题与状态

- 顶栏提供 **System / Light / Dark**。记住用户选择，跟随系统时响应外观变化。主题覆盖所有功能区、弹窗、表单和图表。
- 深色画布、导航和面板用黑、白与中性灰的明度层次及细分隔线区分。常规控件、焦点框和血缘连线沿用灰阶。“失败”“待重建”等状态用文字标明。已建索引和待建索引的连线在灰阶下也应可辨。永久删除使用红底白字，批量清除选择的绿色约定见[数据集批量操作](#dataset-bulk)。

## Data 模块约定

<a id="sources"></a>

### Sources · 数据源

**Sources** 管理连接、连接测试、同步和可用资产预览。数据库连接表单按引擎显示主机、端口、数据库、用户等适用字段，SQLite 使用文件路径。受管目录可选择根目录、文件范围与解析方式。前端演示标明测试和同步的实际范围。选择哪些数据库表进入数仓，由 **Datasets → Import tables** 完成。

<a id="storages"></a>

### Storages · 存储目标

**Storages** 紧邻 **Sources**。新建、导入和编辑数据集共用同一份目标清单。存储详情列出使用它的活跃和已归档数据集，只有无引用的目标可以删除。

编辑器按类型展示字段。本地目录填写路径，S3 分开填写桶名与可选前缀，PostgreSQL 分开填写主机、端口、数据库、schema、用户名和密码。系统根据字段生成目标地址。**Test connection** 标明演示仅做本地校验，更改连接参数后须重新测试才能沿用成功状态。密码仅在当前表单中临时使用。

<a id="dataset-catalog"></a>

### Datasets · 目录布局与筛选

桌面从左到右依次为 **Data 子菜单 → 文件夹树 → 当前文件夹内容**。文件夹栏紧邻子菜单，两者间用细线分隔，窄屏按相同顺序堆叠。根目录从搜索和表格开始，进入子文件夹后在搜索上方显示路径。

筛选区上接主导航、左接文件夹栏，窄屏紧接文件夹栏下方。**Filters** 提供搜索和数仓层筛选。结果列表直接铺在画布上，用间距与筛选区分开，用细线分隔各行。显示匹配数量，清除筛选时保留当前文件夹。

<a id="dataset-folders"></a>

### Datasets · 文件夹与移动

文件夹行末的 **⋯** 菜单支持重命名、创建子文件夹、移动和删除。**All datasets → ⋯** 用于新建顶层文件夹。在其他行执行操作时保留当前浏览位置。只有空文件夹可删除，归档表也计入文件夹内容。

单表移动、批量移动和移动文件夹共用树形弹窗。展开分支并选择目标后显示完整路径，确认后生效。取消或按 Esc 关闭时保留原位置。**Unfiled** 表示表没有所属文件夹。返回来源列表或根目录使用左箭头，其可访问名称指明目的地。目录树中的 **All datasets** 节点保留文字名称。

<a id="dataset-import"></a>

### Datasets · 创建、导入与数仓层

**Create dataset** 定义来自文件、受管目录或 URL 的数据集，也可基于上游数据集定义 DWD 明细表。保存后可运行摄取或物化。**Create dataset** 与 **Manage layers** 使用各自的图标，放在文件夹栏顶部，提供悬停提示、可访问名称和键盘焦点。新建数据集默认使用当前选中的文件夹。

**Import tables** 从同一工具栏打开独立页面。选择数据库连接，搜索并勾选多张表，统一指定原始层、存储位置和目标文件夹。源表清单标明哪些表已导入或已归档。用返回箭头恢复进入时的目录和筛选。**ODS / DWD** 表示加工层级。

<a id="dataset-overview"></a>

### Datasets · Overview

**Dataset details** 显示元数据，标题旁提供刷新和归档操作。空数据集显示首次摄取或物化操作。**Folder** 行显示路径，单元格末尾放置带边框的 **Move to folder**。**Domain** 和 **Subjects** 各占一行，与[分类管理](#taxonomy)共享赋值。

<a id="dataset-bulk"></a>

### Datasets · 批量操作

- 批量工具栏支持跨页勾选。已选数量后，首个操作 **Clear selection** 使用绿底白字。运行、导出、移动、归档使用普通按钮，**Delete selected** 排在最后，使用红底白字。所有批量按钮等宽等高，明暗两种主题均遵守这一顺序和配色。普通表单的取消和返回沿用中性样式。
- 归档和删除的确认弹窗列出选中数量和名称。归档可恢复。永久删除前检查下游引用，包括归档中的下游表。操作结果在当前列表反馈。

<a id="dataset-retrieval"></a>

### Datasets · Retrieval

文档可配置 RAG 的解析、分块、嵌入和索引，界面标明何时需要重建。结构化表按字段设置过滤、返回和等值查询索引，保存后即时生效。字段索引作用于当前数据集的物化记录。

<a id="dataset-preview"></a>

### Datasets · Data preview

首次读取第 1 页，每页最多 **15 条**。结果下方显示当前范围与分页控件，翻页时加载所选页。结构化表在此添加条件、设置 **Row limit** 并执行 **Run query**。行数上限作用于整次查询。文档可在此试搜已构建的索引。打开文档可查看全文，打开表记录可检查字段值，两者均显示来源定位。其他列表按其内容密度确定页大小。

<a id="dataset-lineage"></a>

### Datasets · Lineage

打开具体表后，从 **Lineage** 查看血缘。图以当前表为中心，展示实际配置的上游、下游和索引。选择节点在当前视图检查信息。

<a id="jobs-archive"></a>

### Jobs 与 Archive

- 单表的 **Schedule** 设置计划，显示最近一次执行结果。跨表调查并重试失败作业、查看运行详情或统一编辑计划，从 **Jobs** 进入。详情可展示关联作业的名称、标识、状态和时间。
- 在详情或列表执行归档后，结果在原处反馈。**Archive** 集中浏览和恢复已归档数据集。归档关闭调度，暂停结构化查询并撤下文档索引，保留数据与设置。恢复后，表可以重新查询，文档需重建索引，计划需手动启用。

<a id="taxonomy"></a>

### Taxonomy · 业务域、主题与覆盖情况

- **Domains** 和 **Subjects** 各自管理定义与成员。每项资产可有 **一个主业务域、多个主题**，两者都可以留空，分别保存。主题可以直接用于任何域，也可以先给无域的资产添加主题。
- 目录行的 **Add datasets** 只更新当前维度。从域目录加入会设置主业务域，从主题目录加入会追加该主题。两处与 **Datasets → Overview** 共享分类。资产归档后保留分类，恢复后可继续编辑。
- **Unassigned** 分别统计缺少当前维度的活跃资产。**Coverage** 只按实际使用的归类汇总数据源和数据集数量，包括只填一项的情况。一张表有多个主题时计入各自的主题。EU4、Anbennar、Real History 等语料来源作为独立维度维护。
